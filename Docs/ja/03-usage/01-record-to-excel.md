# 3.1 Excel を扱う

> この章は **データ作業者** のための案内です。Excel シートをどのような形で埋めれば Sdp がそのまま取り込むのかを整理します。標準ヘッダーを除けば、シート構成を好きなように決めてよいというのが Sdp の長所の 1 つです。C# 側で Record を作成する流れは [3.3 最初の Record を定義する](./03-first-record.md) で扱います。

## 作成するシートの例

この章を通して扱うシートは次のような形です。

|       | **A**  | **B**    | **C**       | **D**   | **E**        |
|-------|--------|----------|-------------|---------|--------------|
| **1** | Id     | Name     | Memo        | Price   | Category     |
| **2** | 1      | Potion   | 回復アイテム  | 100     | Consumable   |
| **3** | 2      | Sword    | 基本の剣      | 5000    | Weapon       |
| **4** | 3      | Shield   | 基本の盾      | 4000    | Armor        |

- **1 行目がヘッダー**、**2 行目からデータ** です。
- `Memo` はデータ作業者同士でのみ見るメモ用カラムです。Record 作業者に伝えていないカラムはそのまま無視されるため、シート内に自由に置いておけます (詳しくは [参考カラムはそのままにしてよい](#参考カラムはそのままにしてよい))。
- `Category` のように決まった値の一覧から 1 つを選んで記入する **enum カラム** は、値の名前をそのまま記入します。

カラム名の大文字・小文字の表記は、Record 作業者と一度合意したらそのまま維持します。

</br></br></br>

## ヘッダーが始まるセル

シートの最初のヘッダーが必ず `A1` である必要はありません。**どのセルから始めても構いません**。上や左にシートのタイトルや、このシートがどんなデータを含むのかを書いておきたい場合は、その分ずらしてヘッダーを始めても大丈夫です。

|       | **A** | **B**             | **C**    | **D**     | **E**   | **F**        |
|-------|-------|-------------------|----------|-----------|---------|--------------|
| **1** |       | アイテムテーブル    |          |           |         |              |
| **2** |       | ショップに表示されるアイテムの基本情報 | |    |         |              |
| **3** |       | Id                | Name     | Memo      | Price   | Category     |
| **4** |       | 1                 | Potion   | 回復アイテム | 100     | Consumable   |

この場合、開始セルは `B3` になります。`A` 列と `1`, `2` 行は抽出器が読まない自由領域なので、シートのタイトルやこのテーブルがどんなデータを含むのかといった説明を書いておくのに適しています。開始セルの位置は Record 作業者と一度合意しておけばよく、1 つのプロジェクト内のすべてのシートが同じ開始位置を使う方が単純です。

</br></br></br>

## 参考カラムはそのままにしてよい

備考やメモのように、シート内だけで見たいカラムがよく必要になります。**Record 作業者に伝えていないカラムは抽出時にそのまま無視されます。** 上の例の `Memo` カラムがその場合です — データ作業者同士で共有するメモをシートにそのまま残しておけるという意味です。

逆に、合意されたカラムがシートに **ない場合は抽出が失敗します。**

</br></br></br>

## enum カラム

`Category` のように、あらかじめ決められた値の一覧から 1 つを選んで記入するカラムを **enum カラム** と呼びます。セルには **値の名前** をそのまま記入します。

|       | **A**  | **B**    | **C**        |
|-------|--------|----------|--------------|
| **1** | Id     | Name     | Category     |
| **2** | 1      | Potion   | Consumable   |
| **3** | 2      | Sword    | Weapon       |

表記は **大文字・小文字まで正確に** 一致しなければなりません。`consumable`、`CONSUMABLE`、一覧にない名前 (`Magic` など) はすべて抽出失敗になります。

値の一覧は Record 作業者と合意して受け取っておく情報です。

</br></br></br>

## 文字列セルのカンマ、改行、ダブルクォート

文字列セルにはカンマ、改行 (`Alt+Enter`)、ダブルクォートをそのまま入れても大丈夫です。追加の処理なしに、シートに見えるとおりに保存されます。

|       | **A**  | **B**    | **C**                              |
|-------|--------|----------|------------------------------------|
| **1** | Id     | Name     | Description                        |
| **2** | 1      | Potion   | HP、MP を回復                       |
| **3** | 2      | Letter   | 「こんにちは」と<br>書かれている     |

3 行目の `Description` セルは、Excel セル内で `Alt+Enter` で改行した値です。この改行は見えるとおりに保存されます。

</br></br></br>

## 同じ種類の値が複数 — コレクション

1 行に同じ種類の値を複数入れなければならないことがあります。たとえば、あるアイテムが持つタグの一覧のようにです。2 つの表現方式のうち、データの性質に合う方を選びます。どちらの方式を使うかは Record 作業者と一度合意しておけばよいです。

### 方式 A — 1 つのセルに区切り文字でまとめる

タグが単なるラベルで、個々の値を検討する必要がないなら、**1 つのセルに区切り文字でまとめる** 方式が軽くてよいです。

|       | **A**  | **B**    | **C**               |
|-------|--------|----------|---------------------|
| **1** | Id     | Name     | Tags                |
| **2** | 1      | Potion   | heal, consumable    |
| **3** | 2      | Sword    | melee, iron         |
| **4** | 3      | Shield   | defense, iron       |

</br>

区切り文字はカンマ 1 文字に限りません。`|`、`;`、` / ` のような 1 文字だけでなく、`, `、` - ` のような複数文字からなる文字列も区切り文字として使えます。シート内の値と重ならなければよく、どの区切り文字を使うかは Record 作業者と一度合意しておけばよいです。たとえばタグの中にカンマが入る場合なら、次のように ` | ` (両側に空白 1 つ) を区切り文字として約束し、一目で見やすくしておけます。

|       | **A**  | **B**    | **C**                       |
|-------|--------|----------|-----------------------------|
| **1** | Id     | Name     | Tags                        |
| **2** | 1      | Potion   | heal \| consumable, small   |
| **3** | 2      | Sword    | melee \| iron, starter      |

</br>

- 1 行が短く、一目でまとまって見えます。
- **後で項目数が増えても合意なしにそのまま適用されます** — セルに項目を追加するだけです。
- ただし、Excel 自体で個々の項目単位での並べ替え、フィルタリングは難しいです。

</br></br>

### 方式 B — 複数のセルに展開する

タグを 1 つ 1 つ検討したり、セル単位で並べ替え、フィルタリングしたいなら、**複数のセルに展開する** 方式が有利です。

|       | **A**  | **B**    | **C**     | **D**        | **E**     |
|-------|--------|----------|-----------|--------------|-----------|
| **1** | Id     | Name     | Tags[0]   | Tags[1]      | Tags[2]   |
| **2** | 1      | Potion   | heal      | consumable   | small     |
| **3** | 2      | Sword    | melee     | iron         | starter   |
| **4** | 3      | Shield   | defense   | iron         | starter   |

</br>

- Excel のフィルター、並べ替え機能が各項目を独立して扱えます。
- カラム数が決まっているため、増やしたり減らしたりするには Record 作業者との合意が必要です。
- セルを空にしておきたいときは、どのトークン (`"-"`、`空のセル` など) を空の値として約束するかを一度合意しておけばよいです。

</br></br>

2 つの方式の選択は次のように考えられます。

- カラム数が頻繁に増減する可能性があるなら、**方式 A** が管理のしやすさで有利です。
- カラム数が固定で、セル単位の並べ替え/フィルターを活用したいなら、**方式 B** が有利です。

</br></br></br>

## オブジェクトが複数 — オブジェクトの配列

タグのような単純な値ではなく、**複数のフィールドを持つ束** が 1 行に複数入る場合があります。たとえば、1 人の生徒が複数の科目の成績を持つシートです。作業中は、見分けやすい仮のヘッダーで先に書いておく方が自然です。

このようなデータを `数学科目`、`数学点数`、`英語科目`、`英語点数` … のようにフィールドを横にずらりと並べる代わりに **オブジェクトのコレクション** としてまとめておけば、C# コードでは科目数だけ `foreach` ループ 1 つで処理できます。フィールドを並べる方式は、項目が増えるたびにコードもその分増やしながら 1 つ 1 つ扱わなければなりませんが、コレクションにしておけば同じループが項目数に関係なくそのまま動作します。1 行に同じ種類の束が複数あるなら、コレクションで書く方がほぼ常に有利です。

|       | **A** | **B**   | **C**        | **D**     | **E**          | **F**       | **G**         | **H**      |
|-------|-------|---------|--------------|-----------|----------------|-------------|---------------|------------|
| **1** | Id    | Name    | 数学科目     | 数学点数  | 英語科目       | 英語点数    | 理科科目      | 理科点数   |
| **2** | 1     | Alice   | Math         | 90        | English        | 85          | Science       | 88         |
| **3** | 2     | Bob     | Math         | 70        | English        | 95          | Science       | 75         |
| **4** | 3     | Carol   | Math         | 80        | English        | 80          | Science       | 90         |

しかし、自動抽出が動作するにはヘッダーが決まった標準形でなければなりません。上のシートの標準ヘッダーは次のように長くなります。

|       | **A** | **B**   | **C**                 | **D**               | **E**                 | **F**               | **G**                 | **H**               |
|-------|-------|---------|-----------------------|---------------------|-----------------------|---------------------|-----------------------|---------------------|
| **1** | Id    | Name    | Subjects[0].Subject   | Subjects[0].Score   | Subjects[1].Subject   | Subjects[1].Score   | Subjects[2].Subject   | Subjects[2].Score   |

この標準ヘッダーを手作業で揃えるのは簡単ではありません。データの合意が終われば、この部分は **標準ヘッダージェネレーター** が自動で埋めてくれます。次の章で続けます。
