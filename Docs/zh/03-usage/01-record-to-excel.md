# 3.1 处理 Excel

> 本章是面向 **数据作业者** 的指南。它整理了应当以何种形式填写 Excel 工作表，才能让 Sdp 原样接收。除标准表头之外，可以按你最方便的方式组织工作表，这是 Sdp 的优点之一。在 C# 一侧编写 Record 的流程在 [3.3 定义你的第一个 Record](./03-first-record.md) 中介绍。

## 要创建的工作表示例

贯穿本章要处理的工作表是如下形状。

|       | **A**  | **B**    | **C**       | **D**   | **E**        |
|-------|--------|----------|-------------|---------|--------------|
| **1** | Id     | Name     | Memo        | Price   | Category     |
| **2** | 1      | Potion   | 回复道具     | 100     | Consumable   |
| **3** | 2      | Sword    | 基础剑       | 5000    | Weapon       |
| **4** | 3      | Shield   | 基础盾       | 4000    | Armor        |

- **第 1 行是表头**，**数据从第 2 行开始**。
- `Memo` 是仅数据作业者之间查看的备注列。未告知 Record 作业者的列会被原样忽略，因此可以在工作表中自由保留（详情参见 [参考列可以保持原样](#参考列可以保持原样)）。
- 像 `Category` 这样从既定值列表中选择一个填写的 **enum 列**，直接填写值的名称。

列名的大小写写法一旦与 Record 作业者商定，就保持不变。

</br></br></br>

## 表头开始的单元格

工作表的第一个表头不一定必须是 `A1`。**从哪个单元格开始都没关系。** 如果想在上方或左侧写上工作表标题，或写明该工作表包含什么数据，可以相应地错开后再开始表头。

|       | **A** | **B**             | **C**    | **D**     | **E**   | **F**        |
|-------|-------|-------------------|----------|-----------|---------|--------------|
| **1** |       | 道具表             |          |           |         |              |
| **2** |       | 商店中展示的道具的基本信息 | |    |         |              |
| **3** |       | Id                | Name     | Memo      | Price   | Category     |
| **4** |       | 1                 | Potion   | 回复道具   | 100     | Consumable   |

这种情况下，起始单元格为 `B3`。`A` 列和第 `1`、`2` 行是提取器不读取的自由区域，适合写上工作表标题或该表包含什么数据之类的说明。起始单元格的位置只需与 Record 作业者商定一次即可，且一个项目内所有工作表使用相同的起始位置会更简单。

</br></br></br>

## 参考列可以保持原样

经常会需要像备注或说明这样仅想在工作表内查看的列。**未告知 Record 作业者的列在提取时会被原样忽略。** 上例中的 `Memo` 列就是这种情况 —— 意味着可以把数据作业者之间共享的备注直接留在工作表中。

反过来，如果商定的列在工作表中 **缺失，则提取失败。**

</br></br></br>

## enum 列

像 `Category` 这样从预先确定的值列表中选择一个填写的列，称为 **enum 列**。在单元格中直接填写 **值的名称**。

|       | **A**  | **B**    | **C**        |
|-------|--------|----------|--------------|
| **1** | Id     | Name     | Category     |
| **2** | 1      | Potion   | Consumable   |
| **3** | 2      | Sword    | Weapon       |

写法必须 **包括大小写在内完全** 一致。`consumable`、`CONSUMABLE`、不在列表中的名称（如 `Magic`）都会导致提取失败。

值列表是通过与 Record 作业者商定而获得的信息。

</br></br></br>

## 字符串单元格中的逗号、换行、双引号

字符串单元格中可以直接放入逗号、换行（`Alt+Enter`）、双引号。它们会原样保留为工作表中所见的样子，无需额外处理。

|       | **A**  | **B**    | **C**                              |
|-------|--------|----------|------------------------------------|
| **1** | Id     | Name     | Description                        |
| **2** | 1      | Potion   | 回复 HP、MP                         |
| **3** | 2      | Letter   | 上面写着<br>「你好」                |

第 3 行的 `Description` 单元格是在 Excel 单元格内用 `Alt+Enter` 换行后的值。该换行会原样保留为所见的样子。

</br></br></br>

## 同种类型的多个值 —— 集合

有时需要在一行中放入多个同种类型的值。例如，一件道具所拥有的标签列表。从两种表现方式中选择适合数据性质的一种。使用哪种方式只需与 Record 作业者商定一次即可。

### 方式 A —— 在一个单元格中用分隔符归拢

如果标签只是标签，无需检查单个值，那么 **在一个单元格中用分隔符归拢** 的方式比较轻量、好用。

|       | **A**  | **B**    | **C**               |
|-------|--------|----------|---------------------|
| **1** | Id     | Name     | Tags                |
| **2** | 1      | Potion   | heal, consumable    |
| **3** | 2      | Sword    | melee, iron         |
| **4** | 3      | Shield   | defense, iron       |

</br>

分隔符不限于单个逗号字符。不仅 `|`、`;`、` / ` 这样的单个字符，`, `、` - ` 这样由多个字符组成的字符串也可以用作分隔符。只要不与工作表中的值重叠即可，使用哪个分隔符只需与 Record 作业者商定一次即可。例如，如果标签中含有逗号，可以像下面这样约定用 ` | `（两侧各一个空格）作为分隔符，使其一目了然、更易查看。

|       | **A**  | **B**    | **C**                       |
|-------|--------|----------|-----------------------------|
| **1** | Id     | Name     | Tags                        |
| **2** | 1      | Potion   | heal \| consumable, small   |
| **3** | 2      | Sword    | melee \| iron, starter      |

</br>

- 一行较短，一目了然地归拢在一起。
- **即使以后项目数量增加，也无需商定即可原样适用** —— 只需在单元格中添加项目。
- 但是，在 Excel 本身按单个项目为单位进行排序、筛选比较困难。

</br></br>

### 方式 B —— 展开到多个单元格

如果想逐个检查标签，或想按单元格为单位进行排序、筛选，那么 **展开到多个单元格** 的方式更有利。

|       | **A**  | **B**    | **C**     | **D**        | **E**     |
|-------|--------|----------|-----------|--------------|-----------|
| **1** | Id     | Name     | Tags[0]   | Tags[1]      | Tags[2]   |
| **2** | 1      | Potion   | heal      | consumable   | small     |
| **3** | 2      | Sword    | melee     | iron         | starter   |
| **4** | 3      | Shield   | defense   | iron         | starter   |

</br>

- Excel 的筛选、排序功能可以独立处理每个项目。
- 由于列数固定，要增加或减少列数需要与 Record 作业者商定。
- 想留空单元格时，只需商定一次用哪个标记（`"-"`、`空单元格` 等）表示空值即可。

</br></br>

两种方式之间的选择可以如下考虑。

- 如果列数有可能频繁增减，**方式 A** 在管理便利性上更有利。
- 如果列数固定，且想利用按单元格的排序/筛选，**方式 B** 更有利。

</br></br></br>

## 多个对象 —— 对象的数组

有时进入一行的不是像标签那样的简单值，而是 **带有多个字段的组合** 多次出现。例如，一名学生拥有多个科目成绩的工作表。在作业过程中，先用易于辨识的临时表头写下来比较自然。

与其把这类数据像 `数学科目`、`数学分数`、`英语科目`、`英语分数` … 那样把字段横向一字排开，不如归拢为 **对象的集合**，这样 C# 代码就能用一个 `foreach` 循环按科目数量迭代来处理。一字排开字段的方式，每增加一个项目就要相应地增加代码、逐个处理；而归拢为集合后，同一个循环无论项目数量多少都能原样运行。如果一行中有多个同种类型的组合，写成集合几乎总是更有利。

|       | **A** | **B**   | **C**        | **D**     | **E**          | **F**       | **G**         | **H**      |
|-------|-------|---------|--------------|-----------|----------------|-------------|---------------|------------|
| **1** | Id    | Name    | 数学科目     | 数学分数  | 英语科目       | 英语分数    | 理科科目      | 理科分数   |
| **2** | 1     | Alice   | Math         | 90        | English        | 85          | Science       | 88         |
| **3** | 2     | Bob     | Math         | 70        | English        | 95          | Science       | 75         |
| **4** | 3     | Carol   | Math         | 80        | English        | 80          | Science       | 90         |

但是，要让自动提取生效，表头必须为既定的标准形式。上面工作表的标准表头会如下变长。

|       | **A** | **B**   | **C**                 | **D**               | **E**                 | **F**               | **G**                 | **H**               |
|-------|-------|---------|-----------------------|---------------------|-----------------------|---------------------|-----------------------|---------------------|
| **1** | Id    | Name    | Subjects[0].Subject   | Subjects[0].Score   | Subjects[1].Subject   | Subjects[1].Score   | Subjects[2].Subject   | Subjects[2].Score   |

手动对齐这个标准表头不是一件小事。数据商定结束后，这部分由 **标准表头生成器** 自动填充。我们将在下一章继续。
